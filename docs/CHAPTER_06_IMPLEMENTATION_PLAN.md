## ۱. یافته‌های معماری سیستم و پیش‌نیازهای پروژه (System Architecture Findings)

فصل ششم ارائه تعاملی دانشگاهی MCP، فصل مقایسه راهبردی و حل پارادوکس مفهومی «API در برابر MCP» است. بررسی معماری پروژه و الگوهای موفق پیاده‌سازی‌شده در فصول ۱ تا ۵ نشان می‌دهد که:

1. **انطباق سناریوی داده‌ای با فصول قبل:** برای پایبندی به اصل پیوستگی شناختی، از همان سناریوی باسابقه استعلام قطعه سخت‌افزاری <span className="font-mono text-cyan-300" dir="ltr">NVMe-4TB</span>، موجودی ۶ عدد و شناسه رکورد انبار `INV-2026-981` استفاده می‌شود. این یکنواختی به مخاطب اجازه می‌دهد تمرکز خود را به جای حفظ نام‌های جدید، روی تفاوت لایه‌های معماری معطوف نماید.
2. **پشتیبانی کامل از دو حالت رندر (Dual Rendering Modes):**
   - **حالت اسلاید (Presentation Mode):** ۶ اسلاید تمام‌صفحه با ترنزیشن‌های انیمیشنی نرم (`AnimatePresence mode="wait"`), ناوبری شناور و کلیدهای کیبورد.
   - **حالت اسکرول روایتی (Scroll Mode):** رندر پیوسته و داستانی بخش‌های شش‌گانه با فاصله‌گذاری متناسب (`space-y-24`) و دسترسی درجا به ویجت‌های تعاملی.
3. **پرهیز از وابستگی‌های جدید (Zero New Dependencies):** تمامی کامپوننت‌ها صرفاً با تکیه بر بسته‌های موجود پروژه شامل `next@16.4.6`, `react@19.3.0`, `tailwindcss@4.3.3`, `motion@14.13.0` و `lucide-react` پیاده‌سازی می‌شوند و هیچ بسته خارجی جدیدی نباید نصب گردد.
4. **جداسازی محتوای فنی LTR از چیدمان فارسی RTL:** استفاده مداوم از ویژگی `dir="ltr"` برای بلوک‌های کد JSON، کدهای دستوری، آدرس‌های API و دیاگرام‌های جریان داده در هماهنگی کامل با فونت وزیرمتن.

## ۴. مشخصات فنی ویجت‌های تعاملی آموزشی (Interactive Components Specs)

### ۴.۱. ویجت تعویض‌گر معماری مقایسه‌ای: `ArchitectureComparisonSwitcher.tsx`
* **اینترفیس وضعیت (State):**
  ```typescript
  type ArchitectureMode = 'direct-api' | 'mcp-based';
  ```
* **قابلیت‌های تعاملی:**
  - دکمه سوئیچ دوگانه با انیمیشن فعال و آیکون‌های متناسب (`Layers`, `Network`).
  - رندر گره‌های معماری با Framer Motion:
    * در حالت `direct-api`: نمایش گره‌های:
      `AI Host / Application` (شامل LLM Core ──► Host Application Runtime ──► Host-side Integration Adapter)
      ──► `Inventory REST API` (نقطه انتهایی موجود)
      ──► `Warehouse Database` (رکورد ۶ عدد NVMe-4TB با شناسه INV-2026-981).
      خطوط اتصال با رنگ کهربایی/قرمز هشداردهنده برای کد چسباننده سفارشی.
    * در حالت `mcp-based`: نمایش گره‌های:
      `AI Host / Application` (شامل LLM Core ──► Host Application Runtime ──► MCP Client عمومی)
      ──► `Warehouse MCP Server` (آداپتور سبک پروتکل)
      ──► `Inventory REST API` (دست‌نخورده و بدون تغییر)
      ──► `Warehouse Database` (کاملاً یکسان با حالت قبل).
      خطوط اتصال با رنگ فیروزه‌ای/زمردی استاندارد.
  - تاکید بصری پایدار بر اینکه دو گره پایینی (Inventory REST API و Warehouse Database) در هر دو حالت کاملاً یکسان و بدون تغییر باقی می‌مانند.
  - کارت توضیحی تغییرات مسئولیت در زیر دیاگرام با تاکید بر مسئولیت هاست و حفظ الزامات امنیتی.

### ۴.۲. نمایشگر کاهش اتصالات تکراری: `IntegrationMatrixDemo.tsx`
* **اینترفیس وضعیت (State):**
  ```typescript
  type MatrixViewMode = 'custom-m-times-n' | 'mcp-m-plus-n';
  ```
* **قابلیت‌های تعاملی:**
  - سوئیچ میان «اتصالات اختصاصی (Custom Ad-hoc)» و «معماری استاندارد (MCP Architecture)».
  - نمایش ۳ برنامه هوش مصنوعی در سمت راست:
    1. محیط توسعه یکپارچه (IDE Assistant)
    2. دستیار دسکتاپ (Chat Desktop)
    3. ایجنت مستقل (Autonomous Agent)
  - نمایش ۳ سرویس خارجی در سمت چپ:
    1. انبار سخت‌افزار (Inventory REST API)
    2. پایگاه دانش سازمانی (Knowledge Base API)
    3. سامانه صدور تیکت (Support Ticket API)
  - **تمایز بصری دقیق اتصالات زمان اجرا از واحدهای پیاده‌سازی:**
    * **اتصالات ران‌تایم (Runtime Connections):** در هر دو حالت، هر ۹ خط ارتباطی فعال میان ۳ برنامه و ۳ سرویس به تصویر کشیده می‌شوند (هرگز به صورت گمراه‌کننده تنها ۳ خط ران‌تایم رسم نمی‌شود؛ زیرا در سناریوی اتصال کامل، روابط منطقی ران‌تایم همواره ۹ رابطه است).
    * **در حالت `custom-m-times-n`:** خطوط با رنگ‌های پراکنده و متقاطع رسم شده و برچسب «۹ کد چسباننده، نگاشت و اعتبارسنجی اختصاصی مجزا» را نشان می‌دهند.
    * **در حالت `mcp-m-plus-n`:** همان ۹ خط ران‌تایم از گذرگاه‌های استاندارد هماهنگ عبور کرده و نشان داده می‌شود که کل سیستم تنها به ۳ پیاده‌سازی کلاینت در هاست‌ها و ۳ سرور مستقل MCP نیاز دارد ($M+N=6$ واحد پیاده‌سازی استاندارد و بازاستفاده‌پذیر).
  - نشان الزامی آموزشی (Educational Disclaimer):
    «مدل مفهومی آموزشی؛ نمایش ساده‌سازی‌شده کاهش افزونگی در واحدهای پیاده‌سازی ($M+N$ پیاده‌سازی مستقل در برابر $M \times N$ کد سفارشی)، نه کاهش اتصالات اجرایی در زمان ران‌تایم. در اتصال کامل، تعداد روابط ارتباطی منطقی ران‌تایم همچنان ۹ کانال است.»

### ۴.۳. کاوشگر سه‌لایه تکنولوژی: `TechnologyTriadViewer.tsx`
* **اینترفیس وضعیت (State):**
  ```typescript
  type TriadTab = 'model-layer' | 'protocol-layer' | 'service-layer';
  ```
* **قابلیت‌های تعاملی:**
  - سه تب تعاملی برای انتخاب لایه:
    1. لایه مدل (Model Layer — Function Calling)
    2. لایه پروتکل (Protocol Layer — MCP JSON-RPC 2.0 با نسخه 2026-07-28، متد `server/discover` و هدرهای ترابری)
    3. لایه وب‌سرویس و داده (Service Layer — REST API مبتنی بر OpenAPI / SQL)
  - نمایش کد نمونه متناظر در هر تب:
    * تب ۱: ساختار JSON ابزار مدل (`tool_calls` با ورودی `sku: "NVMe-4TB"`).
    * تب ۲: فریم استاندارد پروتکل MCP (`tools/call` با فراداده `_meta` نسخه `2026-07-28` و اشاره به هدرهای HTTP نظیر `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name`).
    * تب ۳: قرارداد OpenAPI و درخواست/پاسخ HTTP REST (`GET /api/v1/inventory/NVMe-4TB` با کد 200 و شناسه `INV-2026-981`).
  - تشریح صریح نقش هر لایه، عدم جایگزینی مستندات توسط کشف خودکار، و رفع سوءتفاهم هم‌پوشانی.
